## Account records export v1

`account-owned-records-v1` produces an authenticated, expiring ZIP containing `manifest.json` and `account-records.json`. It is an account-owned records snapshot, **not a complete statutory data-access response** and not an S21 selected-document package. The UI requires a separate confirmation and an owner-chosen expiry between one minute and seven days ahead. This is artifact access duration, not an invented legal retention period. Local/test only; hosted fulfillment remains closed.

Included: own profile and consent records; own workspace settings; properties and property history; bills, obligations, occurrences, payments and ledger; maintenance/events/document links; timelines; tenant/booking/listing records entered into the owned workspace; assessments/items; notification preferences and legacy reminders; document and every-version metadata (including content hashes, scan/review states and provenance); outgoing invitation/grant metadata and selected scopes without tokens; all owned Construction projects with stages/tasks/budgets/costs/materials/prices/procurement/contacts/updates/events/document links; processing-withdrawal control. Repeatable-read transaction defines the records snapshot. Integer monetary values remain paise strings. ZIP manifest includes records SHA-256; protected retrieval verifies artifact SHA-256 and authorization again after storage read.

Explicitly excluded: original document bytes (separate authorized Vault downloads); extracted text/OCR/AI outputs and prompts; search caches; authentication secrets/session tokens/OTPs; invitation tokens; internal storage locations; raw provider payloads/failures; records only temporarily shared by another owner. Also not included in v1: durable reminder attempt/delivery logs, share-operation payloads, generated export contents, assistant operational logs, privileged audit receipts and system queue/effect records. These operational/derived-data scope decisions need review before a complete statutory disclosure claim. No silent truncation: archives above the current 10 MiB serialized-record bound fail.

Lifecycle: intake AWAITING_POLICY → explicit scope/expiry confirmation QUEUED → durable worker PROCESSING → READY or FAILED. Existing durable attempts retry failures; no arbitrary operator replay. Owner cancellation before/during/after generation blocks later downloads; final CAS prevents a cancelled request becoming READY. EXPIRED blocks retrieval, with worker cleanup of deterministic private keys. Artifact key is recorded before generation for crash cleanup. Account deletion must inventory these keys before removing request rows; current FK cascading alone is not sufficient erasure.

## Intelligence withdrawal

Versioned notice `local-document-intelligence-withdrawal-v1` stops PARSE_DOCUMENT/OCR_DOCUMENT/AI_EXTRACT_DOCUMENT. It does not disable required malware scanning, original-file access or manual categorization. Local parsing is included; live OCR/AI remain unavailable. Absence of withdrawal is not authorization for a new external provider.

Workspace lock serializes affected enqueue/output persistence against withdrawal. Pending affected jobs are cancelled; claimed work checks before provider invocation and after return; worker records cancellation instead of retry on PROCESSING_WITHDRAWN. Review, search document-result/count delivery and assistant document excerpts recheck withdrawal. Existing extracted data is not erased or retrospectively recalled. Audit receipt explicitly states previously dispatched data is not recalled. No re-enable UI is provided. An empty workspace may be created by an explicit owner withdrawal; it contains no fixtures/properties.
