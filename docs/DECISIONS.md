# Sukoon engineering decisions

This file records the reversible decisions used by the current repository. It is not client acceptance, production approval, or a substitute for the source-of-truth documents in `Sukoon_Agent_Starter_Pack/`.

## All-phases foundation decisions — 2026-09-12

- Scope authority is recorded as D-015 in the canonical pack decision register: both roadmaps now scheduled, no paid-provider/private-data/publication/release approval inferred.
- Local operator diagnostics stay closed in hosted environments until stronger auth is implemented. An operator role never supplies owner/delegate file capabilities. Public liveness is separate from optional capability availability.
- Terminal unavailable scans may be owner-retried only on the same current version and durable job with retained evidence, atomic action receipt and maximum10 total attempts. Clean/threat results cannot be reset. No general side-effect replay capability was inferred.
- Privacy request intake uses a new additive durable model with AWAITING_POLICY/CANCELLED states; no retention durations or fulfilled exports/deletions are invented. The current schema cascades intake records on account deletion; approve and implement required minimal audit/tombstone handling before adding deletion execution.
- Logout clears private client state before awaiting the server and rejects stale account-epoch replies. This is not full idle expiry/no-flash browser acceptance.

## Decision hygiene

2026-09-12 continuation: the explicit owner brief authorizes erasure only in newly provisioned synthetic run-owned targets. Implemented a whole-disposable-environment fence and independent opaque deletion catalog, never activation for the normal review DB or a production policy. Source/restore names, roots and markers must match; restore readiness is not inferred from a successful pg_restore. Historical backups remain private and physically retained. OA04 still governs live retention, disclosure, shared records and audit/backup expiry. See PRIVACY_ERASURE_RECOVERY evidence.

O01 records are manual assertions: co-owner names confer no permissions, loan balances have no live lender provenance, and insurance dates neither prove cover nor renew/create a payment. Owner explicitly confirms separate schedules; UI retry keys cannot duplicate a schedule. The existing versioned property/history and obligation/reminder architecture is reused.

Changes affecting privacy, legal content, production, scope, provider spend, retention, or the accepted visual direction require an explicit updated decision and human approval. Missing credentials are recorded as blockers; they are not replaced with fake integrations.
